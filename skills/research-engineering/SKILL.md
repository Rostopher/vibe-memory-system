# Research Engineering

面向研究型 Python 工作。通用开发、接入与阶段性整合可结合可用的
`evolutionary-development`；本 skill 负责数据、计算和研究解释的边界。

## 选择工作方式

- 技术或方法路线尚不清楚：在隔离的 demo / 实验空间验证关键问题。
- 局部数据或行为不清楚：写 `probe_<用途>.py` 做抽样观察或最小诊断。
- 路径清楚：直接实现，按改动影响安排验证。
- 不强制所有任务先写测试，也不要求先制造失败才能改核心代码。修 bug 时，优先获取
  可复现证据；值得长期保护的行为再提炼为标准测试。
- 一次探索可以验证可行但暂不接入。结论注明适用条件，区分受阻、证据不足和已证伪。

## 数据与语义

- 未知体量先查看文件大小、字段和少量样本，检查编码、缺失、类型和主键。
  CSV 可用 `nrows` / `chunksize`，二进制表格用相应读取器。按规模选择
  `usecols`、`dtype`、分块或全量计算，不无必要把整份数据加载进上下文。
- 原始数据、派生数据和结果有明确来源与输出位置；避免无意覆盖原始输入。
- 修改清洗、连接、筛选或变量构造时，检查受影响的行数、键唯一性、连接基数、
  样本流失和单位 / 时间口径。选择与实际风险相关的检查，不机械执行所有项目。
- 记录足以复算的代码仓库与版本、数据版本或摘要、配置、环境和必要的随机种子；
  涉及模型调用时记录实际模型、prompt / 参数及不确定性。
- 观察结果、解释和研究结论分开。数据或规格有意改变时解释结果差异，
  不把“系数仍显著”当作正确性标准，不为通过测试维持错误的旧结果。

## Probe 与正式测试

- `probe_*.py` 用于观察、诊断与比较；允许依赖本次现场条件，注明运行入口与输入。
- 正式测试使用框架约定（Python 通常为 `test_*.py`），输入和条件可控，
  可重复执行并明确通过 / 失败，保护行为或契约而非偶然的源码拼写。
- 有 `assert` 不自动成为回归测试。把探针中的稳定样例和有价值的断言提炼进测试体系。
- 现有 `_test_` 按内容逐步区分探针、正式测试和工具；迁移需单独安排，不批量改名。
- 新回归规格应检查未打算改变的旧规格；固定输入与配置后按适当数值容差比较，
  必要时使用手算样例、独立实现或排序不变性等依据。
- 共享数据处理、公共接口或基础计算变化扩大验证范围。运行项目已约定的核心检查，
  报告实际覆盖和缺口，不把成功退出或一次 probe 当作完整验收。
- 逐步在测试入口维护“关键能力 / 数据契约 → 测试与命令 → 缺口”，memory 只链接该入口。

## 路径与产物

- 使用 `pathlib.Path`。脚本自带资源可基于 `Path(__file__).resolve().parent`；
  数据根与输出根也可以来自明确配置或命令行参数。输出可追踪，不强制与代码同目录。
- 不隐式依赖 cwd 定位项目资源。CLI 若约定相对路径以调用位置为基准，应显式解析并
  报告最终位置；notebook / REPL 显式提供项目根或数据根，不假设有 `__file__`。
- 文本默认 UTF-8；结果、日志、缓存与临时探针产物分清用途，避免混入正式结果。
- 退役探针前确认有用代码、必要输入和运行条件可恢复；仍用于接入、示例或基准的可保留。

## 错误与降级

- 暴露真实错误，禁止吞错、隐式替换数据或把部分失败伪装成正常完成。
- 按已有策略执行的有界重试、显式失败记录和诊断，通常可在原授权内完成，
  不为常规工程选择逐项索要确认。
- 新增替代算法、跳过样本、填充值或降级若改变研究口径、样本定义、统计解释、
  结果承诺或超出原授权，应先说明影响并取得用户决定。
- 已采用的降级记录原因、影响样本和结果状态，汇总其比例；字段按下游需要设计。
  不预埋没有需求或证据支持的多套 fallback 路径。

## 环境与绘图

- 优先项目 `uv + venv`；否则使用已经可用且兼容的环境，只有选择会实质影响结果时再询问。
- 不向代码、模板或公共文档写入个人私有环境路径、账号或凭证。
- 绘图按项目与受众选择语言、字体和样式；需要中文时检查目标环境字体可用。
  图表应能追溯到数据、配置和生成入口。

## 收尾

按本轮约定交付实现、验证结果和局限；接入必需的整理当次完成。
可独立实施的跨模块 Consolidate 提出证据与范围，交由用户决定，不自行扩大任务。

以完整工作单元为记忆更新节点。到交付时询问是否收束、是否更新 memory；确认后
集中记录成功和失败探索、版本、证据及重试条件。复杂排障可保留长文，不随每个
小改动或试错反复写入。用户已授权记忆更新时直接完成，不重复确认；暂缓时只在
交付中说明必要的文档不一致，不继续误用旧结论。
