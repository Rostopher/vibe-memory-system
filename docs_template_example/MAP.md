# Map

> **职责**：把概念、接口、feature、论文图表或最终产物映射到对应的代码文件、runner、上游输入和中间产物。它是“指针与对照”的 single source of truth，不写长篇叙事。

---

## 什么时候需要本文件？

当项目里出现以下情况时，`MAP.md` 往往很有价值：

- Agent 很难只靠语义搜索快速定位实现位置
- 一个 feature 由多个模块共同完成
- 一个 API、产物或页面需要映射到具体代码文件
- 一个论文图表或报告结论需要映射回输入、代码和中间产物

## 使用方式

- 写清“用户看到的东西”或“项目中的概念”
- 对应到“代码入口 / 产物 / 上游数据 / 导出链路”
- 保持简洁，只写对照关系与必要备注

## 示例结构

| 概念 / 产物 / Feature | 对应文件 / 入口 | 上游输入 / 中间产物 | 备注 |
|---|---|---|---|
| Feature A | `src/...` | `data/...` | 由哪些模块共同完成 |
| API B | `app/api/...` | `services/...` | 对外接口，内部依赖链路 |
| Figure C | `paper/...` | `results/...` | 论文资产与上游脚本映射 |

## 规则

- 只写映射，不写大段背景说明
- 如果某项映射已经稳定，应尽量在这里维护单一真相源
- 若和 `OVERVIEW.md` 或 `RUNBOOK.md` 重叠，优先让它们保留摘要，本文件保留细粒度对照
