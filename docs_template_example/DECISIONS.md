# Decisions Log

> **职责**：沉淀“为什么这么做”的关键决策，避免重复讨论。所有已经形成稳定结论的方法、口径、架构和流程决策，都应在这里留痕。

> **边界说明**：`DECISIONS.md` 记录的是“已经做出的决定”，不是完整讨论过程。
>
> - 如果内容仍是会话中的中间想法、分支方案或未定结论，优先放在 `SHORT_MEMORY/`
> - 如果内容是某次探索或碰壁后的完整记录，优先放在 `archive/`
> - 如果内容是当前实现推进到哪一步，优先写在 `STATUS.md` 或 `REPO_STATUS.md`
> - 如果内容是长期规则或 contract，稳定后也应同步体现在 `CONVENTIONS.md`

---

## 记录规则

- 只追加，不删除
- 若新决策推翻旧决策，写：`supersedes DEC-xxx`
- 每条必须包含：背景 / 结论 / 理由 / 影响范围
- 只记录足够稳定、值得后续反复引用的决策

## 模板

```markdown
### DEC-xxx: 决策标题 (YYYY-MM-DD)
**背景**：
**结论**：
**理由**：
**影响范围**：
```

## 什么时候应该写进这里？

适合写入 `DECISIONS.md` 的情况：

- 你明确选择了一种架构，而不是另一种
- 你统一了一个会长期复用的方法口径
- 你为项目建立了某个稳定规则或约束
- 你需要让后续 Agent 和人知道“为什么现在是这样”

不适合直接写入这里的情况：

- 还在比较多个方案
- 只是一次临时调试过程
- 只是当前状态更新，没有形成明确决策
